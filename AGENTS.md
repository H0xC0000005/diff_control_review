# AGENTS.md

## Purpose and scope

This repository owns independent literature, methodology, task-definition
and report reviews. Read PROJECT_CONTEXT.md, REVIEW_INDEX.md, the relevant
collection overview and its latest applicable feedback before editing.
The user instruction for the current task takes precedence over historical
workflow statements in the archive.

## Independent reviews

Organize work by scientific questions, traffic mechanisms, evidence,
alternatives, conclusions and a topic discussion log. Do not impose
implementation A–F phases, phase-named records, component checkpoints or
plan-freezing gates on a review. Retain review orders the user selected.
Preserve historical phase-named records as chronology, clearly identifying
current descriptive documents. Historical implementation instructions in
context_snapshots are quoted data, not active rules for this repository.

## Scientific responsibility

Preserve accepted scientific decisions. Distinguish Fixed, Default,
Hypothesis, Open and Deferred. Do not turn a default into a requirement or
an unproved claim into evidence. Cite primary methods faithfully and
distinguish retained formulas, adaptations and task-specific definitions.
A component's admissibility proof does not establish physical fidelity,
useful gradients or successful control. Do not weaken a failed criterion.
Keep alternatives current when evidence changes their meaning; explicitly
reopen a selected decision before changing it. Explain the smallest
scientific choice and its consequences when approval is needed.

## Feedback and discussion

Use feedback/feedback.md for new repository-level review feedback, or the
topic inbox the user names. Old inboxes are preserved in context_snapshots.
Never overwrite or delete user feedback to mark it handled. Record the
question with its answer in the topic discussion log. Collect follow-up
questions in the written response; do not use interactive console question
prompts unless explicitly requested. Unanswered questions stay open.

## Boundaries

Reviews do not authorize simulator development, dependency installation,
numerical traffic experiments, optimizer runs or publication/messaging to
others. Execute those only with explicit task authorization. Document
compilation, source reading, analytical reasoning and document/link checks
are allowed within review scope. Do not modify the separate urban or VSL
implementation repositories merely because a review suggests a change.

## Reporting and artifacts

Lead with traffic meaning, causal logic and the consequence for the research
question. Assume textbook traffic knowledge, not specialist-paper familiarity.
Explain each candidate's core idea, behavior in a common example, assumptions
and tradeoff before procedures. Favor connected plain prose; avoid internal
decision labels in colleague-facing reports. Keep precise derivations,
extraction and audit detail in supporting records.

Render substantial mathematics as a LaTeX PDF, keep its source beside it,
verify the installed toolchain and document build commands. A single short
notation definition needs no PDF. Put console artifact links on separate
lines. Preserve sources, outputs and provenance; do not silently overwrite
research evidence. Use rg for searches and inspect before editing.

End work with files changed, assumptions, commands/checks, evidence limits,
current topic, agreed conclusions, remaining questions and next allowed
action. Do not substitute an implementation phase status for a review topic.

## Repository hygiene

The migrated misc collections are tracked, not ignored. context_snapshots
are historical source records. Prefer portable relative links. Do not
include secrets or credentials, delete archived papers/results, force push,
or change repository visibility without explicit authorization. This review
repository is public by the user's 2026-10-29 instruction; the separate VSL
implementation repository remains private. Public review hosting does not
authorize publishing private implementation material.
